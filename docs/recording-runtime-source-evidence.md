# Original source evidence in the persistent runtime

The original #268 source journal and files remain authoritative. Runtime indexes reference their original bytes; they do not rewrite these files into another JSON format. The source replay job is owned immediately after the one fixed START anchor and before awaited evidence writes. Metadata failure retains acquisition and provider prefixes and joins all owned work. The original 50 ms acquisition lateness rule and task deadlines remain unchanged.

`source/mapping-records.json` is a source-ordered list of the actual accepted `replay.mapping.v1` SDK records, at most 16 records and 64 KiB. It uses original #268 canonical JSON without LF. Each original mapping includes the frozen provider epochs before the first publication. One `mapping_published` journal event per source has exactly `source_id`, `mapping_sha256`, `source_mapping_sha256`, `record_sha256`, `record_ordinal`, and `mapping_records_sha256`. The final field is the actual original file SHA; the record ordinal and digest select its accepted SDK record.

For U2, `source/controller-settlements.json` is a bare list of the exact actual SDK settlement rows sorted by `instance`, at most 256 rows and 1 MiB, encoded by the original #268 writer without LF. One `controller_settlement_inventory` journal event has exactly `inventory_sha256` (canonical list digest), `inventory_file_sha256` (original file SHA), and `count`. The source terminal summary includes `controller_settlement_inventory_sha256`, `controller_settlement_count`, and `financial_references` (the actual financial router retained references). The original terminal file inventory binds both evidence files. U1 has null settlement inventory digest, count zero, empty financial references, and no settlement file or event. Financial ownership is installed on actual SDK controllers before any request, and closed after all callbacks and SDK cleanup are joined. Frozen scenarios do not themselves create settlements.

The source terminal summary also records `cleanup_finished_ns` sampled after actual owned SDK cleanup and the post-cleanup replay-clock check. A failed or cancelled source keeps its actual counters and prefix. Delivery residuals remain explicitly unresolved; no publication or model cancellation is inferred from queue disappearance. Invalid negative counter partitions fail the run and retain raw counters rather than fabricating a valid summary.

The public native canonical operation iterator exposes `entered_monotonic_ns`, `relationship`, and `predecessor` from its validated original entered/reserved events. These are nonwire reader fields; native4 remains unchanged. They bind source acquisition before actual entry and the exact fill root/retry/escalation chain.
