# Matched original exposure and full lifetime finance

The v2 evaluator compares all original recording groups using complete arm
lifetime money. Its paired recording statistic is sum(candidate money) divided
by sum(canonical A money), with the original minimum of at least 20 recordings
and the frozen paired bootstrap. Source exposure is matched; actual startup,
processing, cleanup and external resource duration remain observed and may
vary. Actual lifetime is never replaced with source duration.

The public declaration validators are
`validate_recording_opportunities`, `validate_exposure_policy`, and
`validate_accounting_policy` in `benchmarks.matched_source_exposure`.
`validate_lifetime_ledger` requires complete typed runtime/native inventories,
original financial artifacts, authoritative controller settlement inventory,
all required resource lanes, external finality, and an externally reviewed
current validity checkpoint. `reconcile_exposure` joins that typed ledger with
`compare_quality_latency` and preserves the original quality/p95 calculations.
The runtime must first validate every original receipt, task, source and answer
lineage before supplying the quality helper; a hash is not independent evidence
that a latency or assessment is true. Assessment runtime/collection/execution
identities are checked again at reconciliation.

`FinancialFixtureReceiptRouter` is an explicit owned bridge for
`FixtureCompletion`. Register the actual pending request and decision hash
before SDK execute. The router receives the actual SDK-issued native entry,
resolves its frozen synthetic scenario, retains original invoice/evidence,
performs actual controller settlement before response waits, and retains the
SDK transition. Its actual settlement inventory digest binds the typed runtime
view. It never infers a real invoice from model usage or a native attachment.
All routers sharing one `FinancialArtifacts` owner share receipt ordinals and
byte/index budgets. The runtime also supplies the collection's shared
`ArtifactBudget`; separate staging/published copies consume separate bytes.

Initial F1 is synthetic only. A complete fixture can establish arithmetic and
structural correctness; its real receipt, isolation, model-quality and backend
truth flags remain false. The original measured/held-out quality gate remains
false for a synthetic comparison plan. Missing native terminals retain every
failed original arm and known received charges while full money stays unknown.
Required proxies, unfinished resources and unrecognized real charges cannot
become zero. Known late financial evidence requires immutable invalidation and
a new reviewed validity checkpoint; sealed ledger bytes are not rewritten.

Focused verification includes actual TextContextCalls/FixtureCompletion/native4
entries and real SDK budget transitions, cancellation and malformed responses,
a prospective Q2/I3 24-recording/72-arm financial fixture, all failed original
arms, joint admission, duplicate claims, orphan evidence and immutable late
invalidation. These fixtures do not demonstrate whole-recording ABC efficacy
or real quality/cost savings. Old formats and elapsed-hour gates are unchanged.
