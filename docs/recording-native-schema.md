# #269 exact schema appendix — proposed for independent approval

Extends approved design SHA256 `22072a241d08cc300a5ad4ed2a5da3d12dde26eb7df013e3189fee6b49bde980`. No wire implementation precedes approval. This appendix freezes keys; mathematical and lifecycle obligations of that design remain mandatory.

## Common encoding and identity

Every listed object is an exact allowlist: missing and extra keys reject. No duplicate JSON keys, nonfinite numbers, bool-as-int, alternate Unicode normalization or implicit defaults. Canonical JSON is UTF-8, ensure_ascii=True, sorted keys, separators=(',', ':'), allow_nan=False; file digests cover exact canonical bytes plus one LF. Document-reference hashes use the existing comparison `plan_digest` canonical object convention WITHOUT LF, explicitly separate from artifact-file hashes. `H` means lowercase64hex; `ID` means unchanged SDK identifier ASCII1..128; integers are nonnegative <=2**63-1 unless a tighter bound is listed. Times are host monotonic_ns, never wall clock or inherited native3 relative timestamps. All objects include exactly the fields below; notation/types in this document are not literal JSON values. Declared tables use frozen order and compact zero-based indices, never post-freeze sorting. All metadata values are structural, no freeform error strings or sensory bodies.

Domain-separated identity hashing uses canonical arrays, not string concatenation: instance=H(['gamst.recording.instance.v1',nonce,entry_ordinal]); scope=H(['gamst.recording.scope.v1',nonce,Q_digest,scope_index]); claim=H(['gamst.recording.claim.v1',provider,account_scope,invoice_id,line_id]). Domain digests use canonical object convention. Claim owner is a separate instance H, excluded from claim identity. Invoice/account/line IDs are bounded ID values, not arbitrary URLs. No empty or normalized aliases.

## SDK and scope interfaces

`RecordingEvaluationSession.from_frozen(declarations, writer, *, run_nonce, execution_ordinal, retain_evaluation_hashes, retain_financial_documents=False)` receives verified detached C/Q/I/P/source/tasks/profiles and optional referenced S/Qallocation/cost/U objects. `declarations` is an exact named mapping with required keys `plan, collection, scope_protocol, instrumentation_protocol, source_manifest, tasks, profiles` and optional keys only `runtime_policy, stream_protocol, allocation_protocol, cost_card`; referenced hash null iff optional object absent. No R accepted. Financial-document retention defaults false, must equal Q.retain_financial_documents; true requires explicit caller consent in addition to hash retention. False rejects any receipt-source/attachment/claims path or frame before reading/writing its body, and no declared attachment admission is possible. Writer is an owned RecordingNativeWriter, not arbitrary callbacks supplying observations.

`stream_scope(binding_index=None)` and `task_scope(original_task_id,binding_index=None)` return immutable cached handles; binding-specific handles have the same scope identity plus an immutable binding index and distinct owner-issued token. A handle without binding is an identity/view only and cannot reserve a call. `bind_semantic_lane(controller,binding_index)` registers explicit controller identity to the frozen semantic lane before activation; multiple provider bindings may share the same controller/lane, but admission uses the selected immutable binding index and exact provider/revision, never a search for the first matching provider. At most8 controller identities, and mapping cannot change after activation; handles expose `evaluation_owner` as the one registered RecordingEvaluationSession. SDKs validate a supported handle class and owner token, not an arbitrary attribute. `TextContextCalls/VisualContextCalls/SmolVLMCalls.execute(..., evaluation_scope=handle)` captures handle before await. Existing construction and omitted keyword behavior unchanged for legacy observer. `reserve_call(..., evaluation_scope=handle)` captures original scope; fixed handle delegation supplies it explicitly. SensorStreams binding receives fixed stream handle and immutable binding index, source IDs and capture locator supplied by #270's source adapter. For direct #267 OpenCV work, `reserve_operation(binding_index, evaluation_scope, operation_kind, capture_refs, request_sha256, evidence_sha256)` reserves before executor scheduling; its `invoke_sync(callback)` commits under the shared lock immediately inside the worker thread and suppresses callback on revoked admission. Async equivalent `invoke(callback)` commits immediately before calling the async callback. Both return actual result and preserve terminal outcomes; publication is reported separately. `bind_backend(binding_index, backend, kind)` registers the actual owned provider object or external callback identity before activation; fixed identities cannot be rebound. Semantic SDK adapters validate the actual completion callable (Text/Visual) or worker object (Smol) against the selected handle before any await; direct source wrappers validate their provider object. Entry resolves this object to exactly one immutable worker ordinal. A callback object is an observation boundary, not ownership of its external HTTP client. No provider factory/import path comes from JSON. Actual source metadata admission is separate from sensory payload.

`bind_mapping(mapping, expected_sha256)` validates #268 mapping and emits one mapping_bound before capture/semantic entry; startup work may precede it. `close(cleanup_finished=True)` means child-owned SDK/thread/provider work finished, never parent reap. Parent uses a distinct final-manifest operation after child EOF and verified wait/reap. Root270 owns its policy U, READY/ACK/playback/answer schemas and final outer manifest; #269 native bootstrap uses no guessed270 frame types.

## Native4 events and capture/evidence locators

Run header context exact keys: `schema_version`=4, `kind`='recording_native', `nonce`:64hex, `invocation_ordinal`:int, `collection_sha256`:H, `scope_protocol_sha256`:H, `instrumentation_protocol_sha256`:H. Header schema/version names are mandatory on each chunk; other identities resolve transitively. Nonce is parent-generated256bits and globally unique.

Event envelope exact keys: `sequence`:int, `monotonic_ns`:int, `event`:enum below, `fields`:exact variant, `previous_sha256`:H, `sha256`:H. Hash covers canonical envelope without sha256; first previous is H(['gamst.recording.events.v1',run_context]). Sequence contiguous0-based, timestamp nondecreasing in commit-lock order; no sorting afterward. <=2048 encoded bytes with LF. Fields use these variants:

- `mapping_bound`: `{mapping_sha256:H}`; exactly once, immutable.
- `reserved`: `{ticket:int, scope:int, binding:int, operation_kind:enum, phase:'cold'|'warm'|'unknown', relationship:'root'|'retry'|'escalation', predecessor:H|null, request_sha256:H, evidence_sha256:H, prompt_sha256:H|null}`. For semantic SDK calls request_sha256 is exactly the retained immutable controller decision_sha256 selected by request_id before reserve, NOT a wire-request or Smol frame digest; prompt_sha256 preserves the existing adapter's explicit prompt/request hashing semantics. For direct source operations request_sha256 hashes a frozen canonical structural descriptor (binding, operation kind, ordered original capture locators), never sensory bodies. No wire identity claim is inferred from either. Ticket contiguous reservation ordinal; refs separately attached, <=16. Phase remains explicitly unknown unless the frozen profile and observed worker milestones establish the declared cold/warm boundary; timing proximity never supplies phase. Root predecessor null; retry/escalation predecessor same owner/evidence and strictly earlier entry.
- `evidence_ref`: `{ticket:int, reference:locator}`. Locator exact tagged variants: capture `{kind:'capture', source_index:int, capture_ordinal:int, record_sha256:H, mapping_sha256:H}` or result `{kind:'result', entry_ordinal:int, result_sha256:H}`. Capture ordinal is original global #268 record ordinal, source/digest must match immutable source inventory; result must have a preceding finished event with the exact digest and belong to the same run; this is raw-result lineage ONLY and cannot claim accepted/stored HumanSense observation provenance. Such observation provenance requires a separately reviewed exact publication locator and is unsupported in this first result variant. Task sharing refs creates no new owner or charge.
- `dispatched`: `{ticket:int}`.
- `entered`: `{ticket:int, entry_ordinal:int, instance:H, worker_ordinal:int}`. Worker ordinal must refer to the ready, not-closed lifetime for the ticket's binding and actual backend object; it cannot be inferred from the latest worker of that binding. Commit grants invocation; if rejected/revoked wrapper MUST skip callback. Native credits returned only when no later entry possible.
- `released`: `{ticket:int, reason:'admission_refused'|'cancelled_before_entry'|'observer_failed_before_entry'|'revoked_before_entry'}`. Only no-entry tickets; exactly once.
- `finished`: `{entry_ordinal:int, outcome:'ok'|'error'|'cancelled'|'timeout', result_sha256:H|null}`. One callback terminal; error strings prohibited. A result digest is not a bill.
- `published`: `{entry_ordinal:int, outcome:'accepted'|'discarded'|'not_applicable'}`. Exactly once after finished; discarded does not erase costs.
- `worker_registered`: `{worker_ordinal:int, binding:int, kind:'process'|'in_process'|'callback'}`. At most1024 registered worker lifetimes/run and256 simultaneously live, counted in active/work budgets; registration consumes reserved event capacity. One actual provider instance/lifetime, registered before work; ordinal contiguous, owner maps object identity exactly once. Restart allocates new ordinal; live provider instances cannot share an ordinal.
- `worker_milestone`: `{worker_ordinal:int, milestone:'spawn_started'|'handle_acquired'|'ready'|'startup_failed'|'reap_confirmed'|'provider_closed'|'thread_joined'|'callback_attached'|'callback_detached'}`. Process-only spawn/handle/reap follows actual owned subprocess lifecycle; in_process never emits process reap. ready/startup_failed are exclusive startup outcomes. provider_closed records actual provider close, thread_joined only owned outstanding thread completion. Callback kind uses callback_attached before ready and callback_detached only after all adapter-owned calls finish; this attests observer detachment, never closure of caller-owned network clients. Callback lifetimes emit neither provider_closed nor reap_confirmed. No child self-reap: the child's parent-owned ProcessProvider children may be reaped by child, but the native emitting process is only reaped by outer parent.
- `work_started`: `{work_ordinal:int, worker_ordinal:int, scope:0, parent_entry_ordinal:int|null, binding:int, kind:'startup'|'reset'|'residency'|'idle'|'close'|'transport'}`. Worker binding must exactly match the referenced immutable registered lifetime; every interval has explicit own start. Delegated task work retains parent entry; scope0 denotes shared worker lifecycle, never migration of the semantic owner.
- `work_finished`: `{work_ordinal:int, outcome:'ok'|'error'|'cancelled'|'timeout'}`.
- `settlement_ref`: `{entry_ordinal:int, receipt_sha256:H, claims_page_sha256:H}`. Optional one complete declared settlement; null implicit unknown. External receipt file immutable strict bounded representation; details below. No fake usage/rate invoices.
- `private_invalidated`: `{reason:'pause'|'reset'|'delete'|'consent_revoked'|'close', affected:int}`; count actual live private mappings<=256, no subject identifiers.
- `incomplete`: `{reason:'journal_failed'|'capacity_exhausted'|'unobserved_boundary'|'cleanup_incomplete'|'source_incomplete'|'financial_admission_refused'|'settlement_unknown', count:int}`; finite categories and compact counts, no repeated per-entry diagnostics.

Every event has one exact variant. Counters derive from admitted entered events by `(invocation,binding,boundary,role)`, never dispatched count. Missing terminal at failed prefix remains outstanding, not fabricated finished. Source capture counters stay #268 inventory; binding-source correspondence must be exact. Streaming validator reconciles refs, ticket/work transitions and prefix failure inventories.

Declared receipt attachment is explicitly a NEW structural format, not an existing vendor invoice parser: exact keys `schema_version`=1, `kind`='recording_declared_receipt', `origin`='application_declared'|'synthetic_fixture', `money_basis`='unknown', `provider`:ID, `revision`:ID, `account_scope`:ID, `invoice_id`:ID, `source_document_sha256`:H, `source_document_bytes`:1..1MiB, `lines`:list1..64. Line exact keys: `line_id`:ID, `quantities`:object mapping frozen cost-card rate IDs to integer0..1e12, `claim_sha256`:H. Every provider/revision rate is present exactly once, no unknown rate; attachment requires nonnull validated original rate-card identity. Attachment canonical file<=65536B, max16384 attachments and64MiB attachment bytes per collection, additionally joint4GiB. One attachment belongs exactly one native owner; its claims must all be unique within attachment and globally. Same logical (provider,account_scope,invoice_id) must retain the same revision+source document hash; changed documents cannot evade duplicate-line detection. This matches existing original ledger invoice identity, with owner deliberately separate.

The original source document is retained as opaque exact bytes, max1MiB each and64MiB combined collection, filename `receipt-source-<sha256>.bin`, hash verified before attachment acceptance. This is identity/integrity only: #269 does NOT parse or authenticate vendor invoice contents or certify that declared quantities match that opaque original. No original invoice parser is silently selected. Source and attachment artifacts require separate external financial retention consent, and count toward total bytes. Only explicitly supplied invoice/account/line identities are accepted; response usage, aggregate provider cost exports without invoice IDs, locally invented line IDs and configured-rate estimates cannot create this attachment. Those remain unknown. #257's proposed OpenAI aggregate exports therefore have no per-call attachment in this schema until a separately reviewed original-line adapter exists. Synthetic fixtures are visibly marked and never become actual receipts.

Claim page exact keys: `schema_version`=1, `kind`='recording_declared_claims', `receipt_sha256`:H (canonical attachment-file hash), `owner_instance`:H, `claims`:list1..64. Each claim exact `{claim_sha256:H,line_index:int}` matches one attachment line; all lines claimed exactly once and no duplicate hashes/indices. Page<=65536B. `settlement_ref` is retained for compatibility with the proposal's event vocabulary but means ONLY complete declared attachment ownership: it never clears controller financial liability, never establishes known money, and `unsettled_entries` remains the count of entries with no externally verified financial settlement (all entries in this initial format). Attachment filename is `receipt-<sha256>.json`, claim-page filename `claims-<sha256>.json`; digests cover canonical file bytes including LF. Frames and all references use these exact content-addressed identities, not caller paths. Each attachment/page belongs exactly one owner; a source document can be shared by distinct original lines but every referenced source must be sealed before attachment, and attachment before claim page/event. Successful final inventory has no orphan receipt sources, attachments or claim pages; missing/reordered/foreign-owner references reject. Public operation index exposes `declared_settlement_ref` and `unknown_liability=true` independently. No oldnative3 monetary report is manufactured.
