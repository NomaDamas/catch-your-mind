# Direct Responses transport and original request evidence

`OpenAIResponsesClient` is an explicit, single-attempt text/single-PNG Responses client. It uses the real SDK TextContextCalls/VisualContextCalls route, an original observer entry binding, a direct TLS connection to `api.openai.com/v1/responses`, and a separately consented `ResponsesEvidenceSession`. It never fetches credentials, retries, follows redirects, chooses a model, or settles a monetary bill. Application credentials and model revision are mandatory. Genuine cloud compatibility is unverified until separately authorized actual calls are evaluated.

The original entered native instance, possible HTTP handoff, response headers, body completion and SDK publication are separate facts. A timeout or disconnection does not prove that remote work stopped. Request IDs are transport correlation, not invoices. The callback result preserves the existing `{text, usage}` SDK schema, `actual_cost=None` and `usage_verified=False`. Original cache-write/media/reasoning usage remains in the original response bytes; absent cache breakdown is unknown rather than zero.

The public `NativeEntryBinding` tagged union preserves native3 task/stream ownership or native4 recording ownership without inventing one schema's identifiers for the other. Its provider/revision and SDK prompt hash must match the prepared request. A public `binding_owner()` snapshot fixes the external evidence owner in advance. Wire-body hashes are distinct from SDK prompt hashes. A request-only wrapper cannot silently bypass the required bound-completion protocol or create another native row.

One client has one preparation/send, no queue. The exact wire body is capped at16MiB, response headers16KiB, selected-header JSON8KiB, original response1MiB, normalized answer8192UTF-8bytes, and output tokens4096. Responses must be non-streaming, non-background, non-stored, tool-free text; image input is the existing prepared PNG in a data URI. HTTP chunk extensions/trailers, compressed bodies, duplicate headers and ambiguous framing are unsupported. Unsupported response/tool/refusal content fails the projection while preserving bounded original bytes. A shared deadline covers connect/write/read. Cancellation and close join owned network tasks and late connection handles; cleanup can outlive the response deadline. Network peers and DNS/kernel work are not promised hard cancellation.

Evidence retention requires both `retain_response_bytes=True` and `retain_financial_hashes=True`. Raw responses may echo private input or sensitive error content. This consent is separate from sensory storage, and those external files survive sensory deletion. No authorization header or request body is intentionally written to evidence. Live request bytes are discarded after the owned write. Clients remain explicitly application-owned and should be closed with their adapters; the evidence session closes all its active/unused leases before sealing inventory. Self/ancestor joins are refused after invalidation. Do not rely on Python string clearing for cryptographic credential erasure.

Every preparation reserves its worst-case original response, manifest, failure tombstone and inventory reference before dispatch. The session has at most1024 preparations,4096 files,64MiB retained bytes and1MiB final inventory. Files are exclusive and ancestors are opened without symlink traversal. A disk failure after possible send poisons the evidence session and leaves cost unknown; a failed filesystem cannot guarantee even a tombstone write. No partial artifact is called complete. Session terminalization does not reclassify a cancelled or uninspected call as free.

`read_responses_evidence(directory, expected_inventory_sha256=...)` verifies original bounded artifact bytes and returns immutable `ValidatedTransportEvidence`. Its `entries()` expose detached manifests and original response bytes. The reader does not authenticate a provider, establish original native ownership, or verify a bill. Reconciliation must independently load the original native3/native4 evidence and compare owner/entry/provider/request identities; caller-authored matching JSON is insufficient.

Host UTC/monotonic bracket samples are retained for inspection. Absolute clock accuracy is unknown, so `count_bucket_verified=False` and ambiguous host-clock assignment are mandatory, even without a detected clock jump. A provider-reported `created_at` is not the native-entry or possible-send time. Daily usage/cost buckets must not be divided into fabricated per-request charges or uniquely assigned from these anchors alone.

Tests use actual loopback HTTP and original SDK/native paths with visibly synthetic accounts, `req_fixture_*`/`resp_fixture_*` IDs and unverified gates. They do not call OpenAI, install dependencies or verify actual monetary savings. Issues257/277 retain genuine provider/receipt/money/whole-pipeline acceptance.

References: [Responses create](https://developers.openai.com/api/reference/resources/responses/methods/create), [request identity](https://developers.openai.com/api/reference/overview#debugging-requests). `gamst.openai.responses.text-image.v1` freezes this SDK's supported projection, not a promise that upstream documentation is immutable.
